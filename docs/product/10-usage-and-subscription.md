# 10 - 商业模式、用量与订阅

> 文档版本：v1.0
> 核心调整：托管模型是增值项；生产化、治理、团队知识和私有化才是主要付费价值。

## 1. 商业原则

1. 本地 BYOK 是开发者获客入口，不强制登录。
2. 不把“替用户支付 LLM token”当作唯一付费理由。
3. 开源/免费能力应足够完成个人试用和本地集成。
4. 团队和企业为协作、治理、评测、可靠性、连接器和支持付费。
5. OEM 是 SDK-first 产品的重要收入来源，应从公共合同阶段保留授权边界。

## 2. 产品分层

| 版本 | 目标用户 | 核心能力 | 收费方向 |
|---|---|---|---|
| Community | 个人开发者、小团队试用 | 本地 Runtime、TS SDK、REST、CLI、MCP、BYOK、基础 PG | 免费或开源核心 |
| Team | 企业内部数据/平台团队 | 共享语义知识、Verified SQL、评测、RBAC、审计、集中 Secret | 按席位 + 环境/实例订阅 |
| Enterprise | 受监管或大型组织 | 私有化、HA、SSO、自定义策略、国产数据库、SLA | 年度合同 |
| OEM / Embedded | SaaS、ISV、开发平台 | 嵌入授权、白标、版本支持、分发权 | 年度授权 / 环境 / 并发 |
| Managed LLM | 不想管理模型账号的用户 | 托管模型路由、配额和账单 | 用量或套餐增值项 |

具体价格在真实试用数据出现前不写死。早期应验证用户愿意为什么付费，再选择计费单位。

## 3. Community 边界

建议免费提供：

- 单用户本地运行。
- OpenAI-compatible BYOK。
- PostgreSQL 基础 Driver。
- NL2SQL、Schema RAG、SQL 安全和人工执行。
- TypeScript SDK、本地 REST、CLI 和基础 MCP。
- 本地运行记录与基础评测工具。

免费版不需要登录，也不因没有 DBAgent 云服务而削弱数据库安全能力。

不建议把所有生产能力永久免费，包括：团队共享知识、集中 Secret、组织策略、合规审计、高可用、SSO、企业连接器和商业分发权。

## 4. Team 付费价值

Team 不卖“更多聊天轮数”，主要销售：

- 团队共享的业务词汇、语义定义和 Verified Query。
- 连接、Prompt/模型策略和知识版本管理。
- NL2SQL 回归评测、失败案例和发布门禁。
- RBAC、审批流和可检索审计日志。
- 集中 Secret 和环境隔离。
- 运行观测、错误聚合和成本分析。
- 多人反馈闭环与知识审核。

这些能力直接降低生产风险和重复维护成本，具有比 token 转售更稳定的毛利。

## 5. Enterprise 与私有化

Enterprise 提供：

- Docker / Kubernetes / 离线环境部署。
- SSO、SCIM 或企业目录集成。
- 高可用、备份恢复和升级策略。
- 自定义数据留存、网络出口和模型路由策略。
- 国产数据库 Driver、专有连接器和兼容性认证。
- SLA、培训、上线支持和安全响应。
- 可选源码托管、长期支持版本或联合开发。

企业版可以按部署环境、数据库实例、活跃用户或年度平台授权组合报价，避免只按 token 计费。

## 6. OEM / Embedded

SDK-first 路线应主动服务以下买家：

- 数据库管理产品。
- SaaS 报表和运营平台。
- 企业研发效能平台。
- AI Agent / Copilot 产品。
- 云厂商或数据库厂商的增值工具。

OEM 合同重点：

- 是否允许再分发和白标。
- 允许的产品、环境和客户数量。
- Runtime 版本、升级和安全补丁期限。
- 支持的数据库、模型和部署方式。
- 事故支持和 SLA。
- 是否包含企业插件和评测能力。

## 7. 用量计量

### 7.1 MVP

本地 MVP 不做账号、支付和云端配额系统，只记录不含敏感内容的运行级指标：

- run id、时间、状态和耗时。
- 模型与 token 数（Provider 返回时）。
- Schema 命中文档数量。
- SQL 安全结果。
- 是否执行、行数和执行耗时。
- 用户反馈：接受、修改、拒绝（后续切片）。

不得记录：API Key、数据库密码、完整数据库结果、未经用户同意的 Prompt/SQL 云端副本。

### 7.2 托管模型

Managed LLM 可以按 token、请求或套餐计量，但在界面上应让用户看到：

- 当前模型。
- 本次/周期用量。
- 限制和重置规则。
- 切换 BYOK 的明确出口。

托管模型计量不得侵入 Community 本地 Runtime 的核心合同。

### 7.3 Team / Enterprise

更有价值的商业计量维度：

- 活跃席位。
- 管理的数据库连接或实例。
- 部署环境数量。
- 并发 Agent run。
- 评测案例数量和运行频率。
- 企业插件、连接器和支持级别。

## 8. 获客路径

### 8.1 开发者漏斗

1. 开源仓库、技术文章和真实评测展示。
2. 十分钟 Quickstart 和可运行示例数据库。
3. 免费 SDK / API / MCP 完成本地价值验证。
4. 团队开始共享知识、连接和评测时升级 Team。
5. 需要私有化、SSO、国产数据库或 SLA 时进入 Enterprise。

### 8.2 内容重点

- 不宣传“输入一句话生成 SQL”的通用 Demo。
- 展示复杂 Schema 下的执行正确率、错误修复和 Verified Query 提升。
- 展示 SQL 安全阻断、审批和审计。
- 展示国内模型、私有化和真实数据库闭环。
- 提供嵌入 SaaS、数据平台和 MCP 客户端的完整示例。

## 9. MVP 中暂缓的商业基础设施

- 注册、登录、邮箱验证码和密码找回。
- 支付、发票、退款和套餐管理。
- 云端 LLM Gateway。
- 设备绑定和防账号共享。
- 团队席位和组织管理。
- 多租户用量服务和复杂 metering。

原因：当前首要风险是产品价值、准确率、安全和接入体验，而不是计费实现。Runtime 的运行事件和用量接口应保留扩展点，但不让商业后台阻塞第一批试用。

## 10. 商业验证问题

试用阶段必须记录并访谈：

1. 用户把 DBAgent 嵌入了什么系统？
2. 最有价值的是查数、诊断、安全、知识复用还是部署？
3. 哪些能力必须团队共享？
4. 用户更愿按席位、实例、环境、并发还是年度授权付费？
5. 私有化和国产数据库是否是成交前提？
6. 用户是否愿意为 Managed LLM 付费，还是坚持 BYOK？
7. 用户修正 SQL 的主要原因是什么？

没有这些数据前，不锁定具体价格和复杂配额规则。

## 11. 商业化进入条件

开始建设 Team/Enterprise 后台前，至少满足：

- 有一组持续使用的外部试用者。
- Headless SDK/API 被真实产品嵌入，而非只在 Demo 页面使用。
- 固定评测集能证明准确率和安全性稳定。
- 已识别至少一个高频团队协作需求。
- 至少两个潜在客户表达对私有化、治理或 OEM 的明确付费意向。
