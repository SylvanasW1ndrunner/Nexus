# SchemaNaut Benchmark 合同

本页定义未来公开比较 SchemaNaut、纯命令执行 Agent 和其他通用 Agent 的方法。当前状态是：**评测方法已定义，
横向结果尚未发布**。在环境、报告和原始证据可复现前，不根据单次演示宣称更快、更省 Token 或全面更好。

## 要回答的问题

1. 在相同模型下，按任务加载的专业 Capability 是否比只使用基础命令执行更容易完成任务？
2. SchemaNaut 在真实端到端任务上的用户结果，与 Claude Code、Codex 等产品的正常工作方式相比如何？
3. 数据库结果引用、完整本地分析和任务恢复，在哪些类型的任务上产生实际收益或额外成本？

## 两类实验必须分开

### 同模型消融

固定模型、Endpoint、生成参数、权限模式、项目快照、外部工具版本和任务文本，只改变工具条件：

- Baseline：14 个基础 Tool，不激活专业 Capability；
- Capability：相同基础 Tool，并允许按任务发现和激活第一方 Capability。

这类实验用于评估 Capability 架构本身，不能混入不同模型质量造成的差异。

### 端到端 Agent 对比

使用 SchemaNaut、Claude Code、Codex 和其他参评产品正式支持的正常入口、默认 Tool 策略及可用模型完成相同
用户任务。这类实验评估完整产品体验，结论必须明确包含模型、Agent Runtime 和工具生态的共同影响。

只有参评产品都正式支持同一模型时，才可以增加“跨产品相同模型”子实验；不能通过非官方适配冒充公平支持。

## 第一批任务集

- Repository：定位并修复跨文件缺陷，运行相关检查并解释改动。
- Git：理解历史、检查 Diff、形成可审查的提交准备结果。
- Database：发现 Schema、编写 SQL、验证结果并解释业务结论。
- Data analysis：SQL 生成完整数据集，Python 完成统计或简单机器学习分析，再解释限制。
- Browser：复用已登录测试 Profile，完成导航、读取、点击、截图或页面测试。
- Cross-tool：组合数据库、Python、工作区文件和文档输出。
- Recovery：在模型 Turn 或长进程中断后恢复，不重复已确认的副作用。

每个任务必须提供冻结输入、成功判据、允许的外部状态、最大运行时间和独立结果校验器。任务文本不针对某个
产品泄露具体工具名称，除非该实验就是测试工具发现能力。

## 公共指标

每次运行至少记录：

1. 任务是否完成；
2. 独立校验器的正确性分数；
3. 墙钟时间；
4. 输入 Token；
5. 输出 Token；
6. 缓存 Token 或缓存命中量；
7. 模型 Turn 数；
8. Tool 调用数；
9. Tool 失败与重试数；
10. 人工批准与补充输入次数；
11. 发送给模型的 Tool 结果字节数；
12. 中断后的恢复结果；
13. Provider 或基础设施失败；
14. 按公开价格或实际账单计算的成本（可获得时）。

成功率和正确性是主指标。Token、时间或调用次数只有在任务结果达到同一正确性门槛后才能作为效率优势解释。

## 环境冻结

报告必须记录日期、操作系统、CPU/内存、Node/Python/数据库/浏览器/CLI 版本、产品版本或提交、模型精确名称、
Provider、Endpoint 区域、生成参数、权限模式、网络条件、数据集 revision、项目提交和是否预热缓存。

同一个实验组使用相同的项目副本和外部服务初始状态。带写入副作用的任务每次从新的隔离快照开始，不能让前一次
运行改变后一次运行难度。

## 报告格式

每份原始运行记录必须包含：

- `scenarioId`、任务文本和任务集 revision；
- 产品、版本、模型、Provider 和环境摘要；
- 开始/结束时间、最终状态与停止原因；
- 指标原始值和校验器输出；
- Tool/批准/恢复事件的有界摘要；
- 产物引用或可复查输出；
- `passed`、`failed`、`skipped`、`infrastructure-failed` 之一；
- 跳过、超时、限流、模型协议失败或外部依赖缺失的明确原因。

聚合报告必须公开样本量、成功率、分位数而不只给平均值，并链接原始记录。Provider 超时、缺少数据库、浏览器
未启动或结果校验器未运行，不能记为通过，也不能从失败率中静默删除。

## 结论规则

- 不用“拥有 Skills/MCP/子 Agent”作为独占优势；参评产品可能同样具备这些能力。
- 不用一个成功案例代表总体性能，也不从失败任务的低 Token 得出效率更高。
- 同模型消融只解释 Capability 的边际影响；端到端对比只解释完整产品结果。
- 所有“更快”“更省”“更准确”必须给出任务范围、样本量、置信区间或离散程度与原始报告入口。
- 架构优势可以在 README 中说明，但性能领先必须等待本合同下的测量结果。
