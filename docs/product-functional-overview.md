# SchemaNaut 总体功能设计

## 1. 产品目标

SchemaNaut 是面向开发者、数据团队和数据库使用者的开源 AI 数据库 Agent：

> Vanna 式嵌入能力 + Wren 式知识增强 + 成熟编码 Agent 的自主工作能力，并以数据库原生计算、明确权限、国内模型和私有部署为基础。

首个开源版本只建设 AI SQL 与共用 Agent 运行时。AI 数据库治理与运维保留为后续扩展方向，不进入当前公开工具、CLI 功能和验收范围。

产品以 TypeScript SDK 和 REST API 为核心，通过 CLI 完成项目初始化、服务启动、Agent 对话、会话、Skills 和 MCP 操作。轻量 WebUI 只承担连接、模型配置与基础 SQL 试用，不建设数据库 IDE。

## 2. 服务方式

| 入口       | 作用                                                           |
| ---------- | -------------------------------------------------------------- |
| SDK        | 嵌入 Node.js 服务、数据产品和自动化流程                        |
| REST API   | 为其他语言和企业系统提供稳定接口                               |
| CLI        | 初始化项目、运行服务、Agent 对话以及 Session、Skills、MCP 管理 |
| WebUI      | 轻量连接、模型配置与基础 SQL 试用                              |
| MCP Client | 按官方协议接入用户维护的 MCP Server                            |
| Skills     | 通过标准 `SKILL.md` 导入工作方法和项目知识                     |

## 3. 公共基础能力

### 3.1 大模型能力

- OpenAI-compatible、Anthropic、Ollama、国内云模型和私有模型。
- Chat、Tool Calling、结构化输出、Embedding 和 Reranker 合同。
- 模型目录与能力元数据查询，不发送能力探测 Prompt。
- 路由、超时、重试、缓存、审计和 Token/金额指标。

文档：[大模型能力](foundation/01-llm-platform.md)

### 3.2 数据库接入

- PostgreSQL 为首个完整实现。
- 统一 Connector、Driver、连接、事务、查询、取消、EXPLAIN 和元数据接口。
- 合同能够继续扩展到数据库集群、数据仓库和云平台。

文档：[数据库接入](foundation/02-database-access.md)

### 3.3 统一资源与状态

- 使用同一模型描述平台、集群、节点、数据库、Schema、表、字段、Job 和 Pipeline。
- `contains` 提供层级主树，其他关系组成资源图。
- 结构事实、查询结果和实时运行状态相互分离。

文档：[统一资源与状态](foundation/03-unified-resource-state.md)

### 3.4 公共类型与合同

- SDK、REST、CLI、WebUI、Connector、Agent、MCP 和 Skills 共用稳定合同。
- 公共合同只描述已经实现的真实行为。
- 内部轨迹、评测结构和协议 SDK 类型不进入产品公共合同。

文档：[公共类型与合同](foundation/04-public-types-and-contracts.md)

## 4. 大模块一：AI SQL 生成与执行

### 目的

通过 Agent 自主检索数据库知识、浏览资源、生成 SQL、提交数据库原生执行，并根据必要结果或数据库错误继续修正。

SchemaNaut 不把整表数据搬进模型做统计。聚合、过滤、连接、窗口和异常检测尽量下推到数据库，Agent 只读取完成任务所需的最小结果。

### 子模块

1. 层级知识目录、业务知识与 Merkle 版本。
2. 精确、全文、可选向量、业务词典和图融合检索。
3. SQL 生成、语法解析和数据库反馈修正。
4. `read / edit / full` 三档权限与单次批准。
5. SQL 执行、独立有界结果、最多两行的临时模型投影和显式结果导出边界。
6. DDL 后知识刷新与外部变化新鲜度检查。

详细文档：[AI SQL 生成与执行](ai-sql/README.md)

### 达到的效果

- 同时支持中文问题、英文 Schema 和中文数据库对象。
- 不向模型预先灌入整个 Schema 或完整结果集。
- 没有 Embedding 时仍可使用精确匹配、全文和图检索。
- 数据库负责数据计算，Agent 负责目标理解、SQL 编排和必要验证。
- 用户能够查看生成 SQL、重要修正、批准和结果，不需要理解内部索引与算法。

## 5. 大模块二：Agent 与扩展运行时

### 目的

提供一个高度自主、可计划、可验证、可恢复和可扩展的共用 Agent 运行时。数据库专业性来自 RAG、数据库工具和少量系统 Skills；通用工作能力来自文件、终端、网络、任务和子 Agent 工具。

### 子模块

1. Session 隔离、项目目录与持久化。
2. 单一自适应 Agent 循环、结构化任务计划和完成验证。
3. 上下文压缩、长期用户偏好和运行恢复。
4. 统一 Tool Registry、动态发现、调度和结果投影。
5. 标准 Markdown Skills 的系统、用户、项目和 Session 作用域。
6. 官方 MCP SDK 驱动的标准 MCP Client。
7. 与主 Agent 能力相同、上下文独立的子 Agent。
8. 通用文件、搜索、终端、网络和产物能力。
9. 许可、用户可见语义事件、集成事件和内部轨迹分层。
10. CLI 项目、Session、Skills、MCP、运行和诊断体验。

详细文档：[Agent 与扩展运行时](agent/README.md)

### 达到的效果

- 简单任务可以快速完成，复杂任务自动建立并持续更新计划。
- 探索由模型自主决定，运行时通过信息增量、重复检测和完成标准避免空转。
- 同一 Session 的对话、计划、结果、批准和子 Agent 保持隔离和可恢复。
- Skills 与大量 MCP 工具按需发现和加载，不持续占用模型上下文。
- Agent 可以生成和修改 SQL、Markdown、CSV、JSON 等普通项目文件。
- 用户只看到理解、决策和结果所需的信息；集成与内部测试各自使用独立事件通道。

## 6. 后续方向：AI 数据库治理与运维

治理与运维在首个开源版本稳定后进入新的产品阶段。届时复用当前数据库接入、资源模型、Agent、MCP 和 Skills，不把治理专用工具提前混入 AI SQL 公开表面。

后续方向包括：

- 指标、日志、配置和变更采集。
- 慢 SQL、执行计划、锁、长事务和容量诊断。
- 元数据、质量、生命周期、权限和血缘治理。
- 单数据库、集群、数据库群和数仓分层聚合。
- 事件驱动分析、人工批准、执行和复查。

## 7. 当前开发与验收原则

1. 文档、公共合同、实现和测试同步更新。
2. 确定性逻辑使用功能测试，数据库行为使用真实 PostgreSQL。
3. Agent 编排使用确定性模型验证计划、工具、权限、修正和完成条件。
4. 真实模型测试显式开启，不把凭据写入仓库、日志和报告。
5. 复杂数据库至少覆盖电商、流量清洗与异常检测、大科学数据三类场景。
6. 用户体验和工程体验分别验收。
7. 不以服务启动或简单连通性测试代替功能、性能和恢复验收。

完整执行顺序、场景数据、阈值和证据格式见[测试链路](test-pipeline.md)。
