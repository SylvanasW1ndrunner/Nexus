# 诊断与沙盒指南

## 全局权限档位

权限在 ~/.schemanaut/config.toml 中全局选择。项目、Skill、MCP Server 或 Capability 都不能自行获得
更高权限。

| 档位 | 预期行为 |
| --- | --- |
| default | 普通工作区操作可继续执行；外部写入、联网和风险动作需要许可。 |
| auto | 除危险、破坏性、凭据相关、管理员、未知风险或被组织策略限制的动作外，其他动作可继续执行。 |
| full-access | 可以移除内置的逐动作许可，但目标校验、组织规则、取消、恢复和动作记录仍然生效。 |

无论选择哪个档位，组织规则都可以拒绝动作或要求许可。决定前请阅读动作摘要。

## 沙盒的实际含义

沙盒是执行属性，而不是标签。SchemaNaut 会报告当前 Host 对请求动作实际能够提供的隔离。

- 如果没有可用隔离，但适用策略允许用户决定，结果为 ask-unsandboxed。
- 如果策略要求隔离而 Host 无法提供，结果为 unavailable。
- 在没有强操作系统沙盒的原生 Windows 上，已完成的命令可以报告自身退出结果，但无法证明完整的
  containment 或进程树终止。取消或终止后，无法证明已停止的子孙进程仍为 unknown。

本轮不声称提供 Windows Job Object containment 保证。即使外层命令受限，也应把容器 daemon、浏览器
runner、notebook 执行和其他外部服务视作独立安全边界。

## 修复、重试与重启

诊断会指出缺少的前置条件和安全的外部修复路径。请在 SchemaNaut 外修复命令、文件、连接、服务、
安全引用或登录状态，然后让 Agent 重试或重新发现。父进程的 PATH 或环境发生变化时，必须重启终端
Host，才能继承新状态。

## 脱敏

诊断文本、命令输出和报告在显示或保存前都有边界并会脱敏。SchemaNaut 不会有意泄露密钥、
Authorization Header、密码、URL 用户信息、完整连接串或 Provider 原始错误正文。若你认为密钥已经
暴露，请停止使用该密钥，在外部提供方处轮换它，并审阅受影响的本地项目数据。
