# 前端 UI 重构设计规格

## 背景

当前 DBAgent Desktop 的旧前端界面已经停止继续演进。旧界面的问题不是单个按钮或局部样式，而是信息架构、工作台布局、登录流程、终端区域和 Agent 区域缺少统一设计基线，导致后续修补成本越来越高。

本阶段从 UI 层重新开始，但保留已经完成的核心能力：Electron 主进程、preload、IPC 合约、数据库连接、SQL 执行、认证、Python 环境、终端服务、插件注册和工作区服务。

## 开发顺序

1. 设计规格：先写清楚信息架构、布局规则、交互边界和验收标准。
2. 低保真结构：只实现布局骨架和导航关系，不接复杂业务。
3. 功能接线：逐个接入认证、项目、编辑器、数据库、Python、终端、插件和 Agent 面板。
4. 用户级验证：用真实业务场景验证每条主路径是否可用。

任何新增 UI 模块必须先有中文规格和验收用例，再进入实现。

## 信息架构

DBAgent 面向数据工程师和分析师，第一屏应该是工作台，而不是营销页。新的 UI 需要包含以下稳定区域：

- 顶部应用菜单：文件、编辑、选择、视图、运行、终端、设置、帮助。
- 左侧活动栏：资源管理器、搜索、数据库、Python、插件、账户。
- 左侧主侧栏：项目文件树和当前功能的导航树。
- 中央编辑区：支持 SQL、Python、Markdown、纯文本，后续接 Monaco。
- 底部面板：问题、输出、终端、端口、查询结果。
- 右侧 Agent 面板：单一 Agent 对话入口，顶部只保留历史、设置、新对话。
- 状态栏：项目、连接、Python 环境、认证状态、编码、行列信息。

## 视觉原则

- 基准风格参考成熟 IDE，但不照抄某一个产品。
- 默认深色主题，使用接近 VS Code 的低对比工作台结构。
- 主题色使用绿色作为 DBAgent 的产品识别，只用于状态、焦点和关键操作。
- 字体优先使用系统 UI 字体，代码区域使用等宽字体。
- 不使用大面积渐变、装饰卡片、营销式 hero 或无业务含义的视觉元素。
- 所有可拖动侧栏和底部面板必须有清晰边界、悬浮反馈和最小/最大宽高约束。

## 核心工作流

- 启动：未登录时显示登录对话框；已登录时进入最近工作区或空工作台。
- 项目：从顶部文件菜单新建或打开项目；项目设置从设置菜单进入。
- 数据库：项目可绑定 PostgreSQL 连接；后续扩展 MySQL 等数据库。
- 编辑：文件树打开文件，中央编辑器根据文件类型高亮。
- SQL：通过编辑器右键或命令运行整篇/选中 SQL，结果进入底部查询结果。
- Python：通过项目设置选择系统、venv 或 conda 环境；脚本主要通过终端执行。
- 终端：底部终端应是真实系统交互终端，支持新增、关闭、切换和分屏。
- 插件：官方能力也按插件机制注册，后续开放第三方插件。
- Agent：本阶段只设计面板入口和对话容器，不实现 Agent 自动执行。

## 组件边界

- Renderer UI 只负责展示、交互和 IPC 调用。
- preload 只暴露受控 IPC API，不引入业务状态。
- main 进程继续承载本地文件、数据库、认证、Python、终端和插件服务。
- shared 包继续作为 IPC、领域类型和公共序列化格式的唯一来源。
- 纯函数工具模块可以继续保留在 renderer 下，但不能绑定旧页面结构。

## 验收标准

- Electron 启动不白屏。
- 新 UI 骨架实现前，最小宿主必须能完成基础 IPC 健康检查。
- 每个新 UI 模块必须有对应中文设计说明和测试清单。
- 关键路径必须使用真实用户场景验证，不只依赖函数级测试。
- UI 改动不得破坏主进程已有测试、shared 类型和打包流程。
