# BetaV0.1.1 认证表单与终端输入加固记录

## 背景

本轮继续处理用户测试中暴露的两个体验风险：

- xterm/ConPTY 可能把终端能力报告写回 shell，导致 PowerShell 里出现非用户输入的乱码。
- 登录、注册、验证码登录、忘记密码表单缺少前端目标格式校验，用户可能点按钮后才收到后端错误。

## 终端输入

- `terminal-input.ts` 新增对 Secondary Device Attributes 的过滤，例如 `ESC [ > 0 ; 276 ; 0 c`。
- 保留方向键、Delete、PageUp、PageDown 等常用交互按键放行。
- 测试新增对 `ESC [ > ... c` 的覆盖，避免 Windows 终端能力探测序列回显为乱码。

## 认证表单

- 新增 `isValidAuthTarget`，在前端统一判断邮箱或手机号是否可用于登录、注册、验证码和重置密码流程。
- 邮箱规则与后端保持一致：必须包含本地部分、域名和后缀。
- 手机号规则与后端保持一致：去除空格和短横线后，允许可选 `+` 和 8 到 20 位数字。
- 登录弹窗在输入无效邮箱或手机号时显示中文提示，不再只表现为按钮不可点击。

## 验证

- `terminal-input.test.ts` 覆盖新增控制序列过滤。
- `auth-form.test.ts` 覆盖邮箱、手机号和错误目标的表单启用条件。
- 该修复属于用户输入路径加固，不改变后端认证规则。
