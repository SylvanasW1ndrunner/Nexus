# BetaV0.1.1 终端能力协商修复

## 背景

用户反馈终端只显示空白区域和光标，无法看到系统提示符，也无法正常交互。

## 根因

Windows PowerShell 启动后会先向终端发送能力查询，例如 `ESC[c`。xterm.js 收到查询后会通过 `onData` 返回终端能力响应，例如 `ESC[?1;2c`。这些响应必须继续写入后端 PTY，PowerShell 才会继续完成初始化并显示 `PS ...>` 提示符。

此前为了处理“自动输入乱码”的问题，前端过滤掉了这类 xterm 自动生成的响应，导致 PowerShell 一直等不到终端能力协商结果，表现为终端空白且无法进入正常交互状态。

## 修复内容

- 终端输入转发策略调整为只丢弃空字符串。
- xterm 生成的能力响应、光标位置响应、窗口状态响应等都会转发给 PTY。
- 保留普通键盘输入、组合键、控制键的完整转发。
- 增加 Windows PowerShell 能力协商测试：创建终端后写入 `ESC[?1;2c`，必须能读到 `PS ...>` 提示符。

## 验证重点

- 新建终端后不应停留在空白光标状态。
- PowerShell 应能显示 `PS 当前目录>` 提示符。
- 用户输入命令后应能正常回显和执行。
- 后续如果仍出现“乱码自动输入”，应从 shell/PTY 模式或 xterm 终端类型兼容性排查，不能再通过过滤能力响应处理。
