# BetaV0.1.1 登录与终端启动门禁

## 背景

用户反馈终端在新建后仍存在显示和输入不稳定问题，同时产品要求未登录不能使用程序。此前渲染端在启动时会直接初始化 IDE shell，并预创建一个终端会话；这会导致登录弹窗背后已经存在终端进程，也会增加隐藏终端、焦点切换和后续新建终端的状态复杂度。

## 本次调整

- 登录状态确认前不再初始化 IDE shell。
- 登录成功后只加载 IDE 设置，不再预创建隐藏终端。
- 用户打开底部终端面板或点击新建终端时，才创建真实 PTY 会话。
- 启动规则抽为 `ide-shell-startup.ts`，用纯函数测试约束“未认证不初始化、已认证只初始化一次”。

## 验收要点

- 未登录启动应用时，不应创建终端 shell 进程。
- 使用测试账号登录后，工作台可进入正常状态。
- 点击底部“终端”或“新建终端”后，应按需创建终端并显示系统 shell。
- 重复认证状态刷新不应重复初始化 IDE shell。

## 测试

- `ide-shell-startup.test.ts` 覆盖认证门禁和只初始化一次的规则。
- 继续复用 `terminal-service.test.ts` 验证真实 PTY 会话、输入输出、错误 shell 回退和清屏。
