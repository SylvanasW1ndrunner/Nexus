# BetaV0.1.1 终端 xterm 生命周期修复

## 背景

用户反馈底部终端打开后空白，只显示光标，无法正常输入命令或看到系统 shell 提示符。

## 问题判断

本次修复针对一个高概率前端生命周期问题：终端视图使用 xterm.js 渲染，但 xterm 创建逻辑依赖了父组件传入的写入回调。父组件在终端输出轮询、状态提示、面板操作时会重渲染，内联回调身份随之变化，导致 xterm 实例被销毁并重新创建。

这个问题会造成：

- 后端 PTY 可能已经启动，但前端视图持续重建，无法稳定展示初始提示符。
- 输入事件绑定被重复释放和重绑，用户看到光标但输入无法可靠写入后端。
- 输出轮询触发的状态更新反过来再次刷新终端视图，形成体验上的空白终端。

## 修复内容

- 将终端输入写入回调在父组件中稳定为 `useCallback`。
- 在 `TerminalViewport` 内使用 `useRef` 保存最新写入回调。
- xterm 创建 effect 只依赖 `terminal.id`，即只有切换到新的终端会话时才重建 xterm。
- 输入事件仍调用最新回调，避免闭包过期，同时避免渲染刷新导致终端实例重建。

## 验证重点

- 新建终端后应显示系统 shell 提示符。
- 终端输入应能写入后端 PTY，并通过轮询回显到 xterm。
- 输出刷新不应清空终端视图。
- 切换、分屏、清空、关闭终端时仍保持原有行为。
