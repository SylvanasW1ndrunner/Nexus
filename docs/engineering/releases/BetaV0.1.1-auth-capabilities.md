# BetaV0.1.1 认证能力与登录界面门禁

## 背景

当前桌面端支持两种认证运行状态：

- 配置 `DBAGENT_AUTH_DATABASE_URL` 后，账号、验证码和密码哈希写入 PostgreSQL。
- 未配置认证数据库时，桌面端提供 `test / test` 本地烟测账号，便于测试包启动体验。

此前前端始终展示注册、验证码登录和忘记密码入口，但本地烟测模式下这些能力不可用，用户点击后只能得到后端错误。这个状态不符合产品级登录体验。

## 修复内容

- `AuthStatus` 增加 `capabilities` 能力字段。
- 主进程根据认证后端填充能力：
  - PostgreSQL 模式：开放账密登录、验证码登录、注册、重置密码。
  - 本地测试模式：只开放账密登录，并提示测试账号。
- 登录表单根据能力动态展示可用入口。
- 本地测试模式不再展示注册、验证码登录和忘记密码入口，避免用户误操作。

## 测试覆盖

- `auth-form.test.ts` 覆盖 PostgreSQL 模式下四类认证入口都可见。
- `auth-form.test.ts` 覆盖本地测试模式只允许账密登录。
- `auth-form.test.ts` 覆盖本地测试模式下注册提交不可用。

## 后续

正式云端账号上线后，继续复用 PostgreSQL 能力模型。短信/邮件发送服务接入时，不需要改变 renderer 表单结构，只需要替换验证码发送实现。
