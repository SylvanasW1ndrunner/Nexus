# BetaV0.1.1 终端与登录体验修复记录

## 背景

本轮修复针对两个阻塞体验问题：

- 底部终端需要像 IDE 内嵌系统终端一样支持真实输入、输出显示、工作目录和会话管理。
- 启动登录验证弹窗需要去掉临时表单感，改善按钮层级、颜色、布局和提示文本。

## 终端修复

- Windows 默认交互终端从 `cmd.exe` 调整为 `powershell.exe -NoLogo`，更贴近 Windows 用户和 VSCode/JetBrains 的默认体验。
- 写入终端后立即触发一次输出读取，同时保留短间隔轮询，降低输入后无反馈的体感延迟。
- 终端视口改为点击后选中并聚焦 xterm，活动终端切换时重新适配尺寸并聚焦，减少焦点抖动导致的无法输入。
- 保留对 xterm 自动能力报告的过滤，避免这些控制序列被 shell 回显为乱码。
- Windows 工作目录验证命令统一改为 `pwd`，避免 PowerShell 与 cmd 行为差异。

## 登录弹窗修复

- 启动登录弹窗不再展示数据库环境变量提示，避免把内部配置暴露给普通用户。
- 登录方式只保留“账密登录”和“验证码登录”主切换，注册与忘记密码改为轻量文本入口。
- 主提交按钮改为整行主操作按钮，验证码发送按钮降级为辅助操作。
- 调整面板宽度、边框、颜色、输入框高度和间距，使其更接近成熟 IDE 的账号弹窗，而不是临时设置表单。

## 验证

- `terminal-service.test.ts` 覆盖真实 PTY 创建、写入、读取、清理输出、工作目录启动和尺寸调整。
- `terminal-input.test.ts` 覆盖自动控制序列过滤和常用交互按键放行。
- `auth-form.test.ts` 覆盖登录、验证码登录、注册和忘记密码的可提交条件。
- TypeScript 和 ESLint 均通过。

## 浏览器验证说明

当前开发会话中 Browser 插件可以加载，但 `agent.browsers.list()` 返回空列表，`iab` 实例不可用；Chrome 控制入口同样不可用。因此本轮无法通过内置浏览器或 Chrome 截图做视觉回归，只能通过代码审查、构建、测试和打包后的 Electron 原生检查验证。该问题属于外层开发工具浏览器实例未提供，不是 DBAgent 应用代码本身的问题。
