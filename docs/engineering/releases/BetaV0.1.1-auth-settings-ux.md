# BetaV0.1.1 账号设置可用性修正

## 背景

IDE 设置中的账号页承担本地账号注册、登录、验证码登录和忘记密码重置入口。该入口后续会对接云端账号体系，但当前阶段账号数据仍按产品要求存储在本地 PostgreSQL 中，因此前端必须先保证用户路径清晰、按钮状态可靠、错误不会被重复提交放大。

## 本次实现

- 抽出 `auth-form.ts`，统一维护账号页表单规则，避免 JSX 中散落登录、注册、验证码登录、重置密码的判断逻辑。
- 手机号和邮箱由同一个账号输入框承载，前端按是否包含 `@` 推断邮箱或手机通道。
- 只有注册、验证码登录、重置密码三个模式允许发送验证码；账密登录不展示无意义的验证码请求行为。
- 注册和重置密码必须同时填写账号、验证码和密码后才允许提交。
- 验证码登录必须填写账号和验证码后才允许提交。
- 账密登录必须填写账号和密码后才允许提交。
- 账号输入变化时清空旧验证码和旧提示，避免用户换账号后误用旧验证码状态。
- 请求验证码、提交账号动作、退出登录期间统一进入 busy 状态，阻止重复点击造成重复请求或错误覆盖。

## 用户体验约束

- 设置页可以在未打开项目时使用，因为登录、注册、IDE 偏好属于全局 IDE 能力。
- 项目设置仍应只在打开项目后出现，避免用户在无工作空间时修改不存在的项目配置。
- 验证码错误、账号不存在、账号已存在等业务错误由主进程 AuthService 返回，前端只负责展示明确结果，不在 UI 层伪造成功状态。

## 测试覆盖

- `auth-form.test.ts` 覆盖手机号/邮箱通道推断。
- 覆盖不同模式到验证码用途的映射。
- 覆盖验证码按钮启用条件。
- 覆盖提交按钮启用条件，确保注册、登录、验证码登录和重置密码不会提交缺失字段的表单。
- 继续复用 `core-auth` 的业务测试验证本地 PostgreSQL 账号策略、验证码策略、密码登录和重置密码行为。
