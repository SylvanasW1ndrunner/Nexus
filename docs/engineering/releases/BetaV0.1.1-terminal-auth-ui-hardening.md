# BetaV0.1.1 终端与登录界面加固记录

## 背景

本轮修复集中在两个用户可直接感知的问题：

- 启动登录弹窗复用设置表单，视觉粗糙，信息层级不清晰。
- 底部终端的会话栏和工作台面板切换栏混在同一行，新建终端后容易挤占或重叠；xterm 初始化产生的控制序列可能被转发到 shell，导致自动输入乱码。

## 实现内容

- 将启动登录改为独立认证弹窗：
  - 顶部品牌区、标题、副标题、关闭按钮分离。
  - 登录/验证码登录/注册/忘记密码使用紧凑分段控件。
  - 输入框、验证码按钮、主操作按钮按产品级登录表单重新排版。
- 将底部终端区域改为两层结构：
  - 第一行只保留“问题 / 输出 / 终端 / 端口”等底部面板切换。
  - 第二行仅在终端面板内显示终端会话、创建、拆分、清空、更多、最大化、关闭等操作。
- 强化终端输入过滤：
  - 过滤 xterm 设备查询、窗口查询、标题设置、光标模式切换等非用户输入序列。
  - 保留方向键、Home/End、Delete、PageUp/PageDown、Ctrl+C、回车等真实交互输入。
- 重建渲染端中文 i18n 文件，修复历史编码损坏导致的中文乱码问题。

## 测试与验证

- `terminal-input.test.ts`：覆盖 xterm 控制序列过滤与常用交互键保留。
- `terminal-service.test.ts`：使用真实 PTY 创建 shell、写入命令、读取输出、清空缓冲、调整窗口尺寸。
- `i18n.test.ts`：断言关键中文界面文案为可读 UTF-8 中文，并扫描常见乱码模式。
- TypeScript、ESLint、Vite 主进程/预加载/渲染构建通过。
- `electron-builder --dir` 打包目录版通过。
- 打包后的 `DBAgent.exe` 在 `ELECTRON_RUN_AS_NODE=1` 下可正常 `require('node-pty')`。

## 后续建议

- 增加 Electron 级 UI 自动化测试，覆盖终端可见渲染、创建终端、输入命令、读取输出的完整用户路径。
- 终端设置后续应支持按项目配置默认 shell，并在界面上展示当前 shell 类型。
