# 发现结构与数据形态

优先通过知识检索和资源浏览定位候选对象，读取最新 Schema、关系和业务知识。只使用工具返回的业务语义内容。

只有元数据不足以完成任务时，才执行小结果集探索 SQL，例如：

- 对 JSON 字段读取少量非空样例或键集合；
- 对枚举字段查询有限的不同值和频次；
- 对时间字段查询最小值、最大值或按区间聚合；
- 对粒度不明的数据查询主键候选和重复分布。

探索 SQL 必须直接验证一个明确假设。获得所需事实后立即转入用户目标 SQL，不要反复读取相同数据，也不要把探索结果自动写入长期知识库。

如果请求引用了阈值、规则、字典、映射或其他“已配置”的业务口径：

- 查找并使用相关配置表或字典表；
- 用户明确要求“必须使用”或“必须连接”的资源必须参与最终 SQL；单独查询该资源只算探索，不算完成；
- 不得凭经验编造阈值、枚举含义或过滤规则；
- 如果配置确实不存在，再向用户说明缺失项。

处理脏 JSON 或流式事件时：

- 先验证 JSON 字段的存在、类型和可转换格式，再在 `CASE` 或过滤后的 CTE 中转换时间与数值，避免一次坏值导致整条查询失败；
- 需要业务事件含义时连接字典表；
- 对业务规则要求的关键字段，过滤缺失值和空字符串；
- 有重复事件时按明确的业务键和到达时间选择一条记录。

单个聚合目标通常不需要创建任务计划。事实充分后应执行一条落实全部明确口径的最终聚合并检查返回结果；回答前逐项核对用户要求的表、连接、阈值、过滤、去重和返回指标是否都在这条最终 SQL 中生效。除非用户要求，不要自行派生额外统计。
