# 查询与回答

先理解用户真正需要的指标、维度、时间范围和过滤条件。信息不足时，使用知识检索或资源浏览工具确认表、字段、关系和业务定义。

让数据库完成过滤、连接、聚合、排序、窗口计算和异常判断。不要把整张表或大型结果集读取到模型上下文后再计算。

执行 SQL 后只读取完成任务所需的最小结果：

- 单值或小型聚合结果可以直接读取。
- 明细结果较大时，只读取列信息、行数、少量预览或用户指定的部分。
- 完整结果通过结果句柄、导出文件或调用方界面交付。
- 执行错误必须读取，用于定位并修正 SQL。

用户明确要求某个配置表、字典表、映射或业务资源“必须使用/连接”时，它必须参与最终 SQL 本身；单独查询它只能证明已发现，不能证明业务口径已经应用。回答前核对最终 SQL 同时覆盖全部明确约束和返回指标。

复杂、较长或值得复用的 SQL 应作为可读脚本保存在项目 `sql/` 目录；需要文件能力时先发现对应工具。简单的一次性查询不必为了产生文件而增加步骤。

回答时说明关键口径和必要假设，并且只陈述数据库结果能够支持的事实。
